# long-task-loop · 长任务循环工作流 Skill

一个**平台无关**的长任务工作流 Skill：先陪你把目标问清楚（你在场答问、最后在文档上签批），再让 AI 自己关起门来一轮一轮把方案做透（不打扰你），三门收敛后集中找你拍一次板，交付可以直接开工的获批方案。

适用于「需要连着做很多轮、容易跑偏、容易返工」的设计类长任务：产品方案、技术方案、运营方案、制度建设等。**只做方案，不做开发实施**。

## 它解决什么问题

| 失败 | 表现 | 本工作流的做法 |
|-|-|-|
| 目标没找对 | 方案写得很漂亮，做完发现解决的是表面症状 | 奠基阶段强制根因下钻、事实逐条用工具核实、思路先调研再定；不过就绪门不许进循环 |
| 中途跑偏 / 反复打断 | AI 每遇到岔路口就来问你，或者自己越改越远 | 目标签批后锁死；循环期间可逆取舍 AI 自己拍板并留回滚记录，只在收尾集中找你批一次 |

## 六段工作流

```
奠基访谈 → 就绪门 → 三锁签批 → 循环 → 收敛（三门）→ 终局批与交付
```

1. **奠基访谈**：结构化访谈四条主线（目标下钻、事实核实、思路基线、框架对齐），成果实时落总控文档
2. **就绪门**：独立评估全部子判据，全部通过才放行
3. **三锁签批**：你在总控文档上对目标锁、事实基线锁、方案框架锁分别发批准评论
4. **循环**：以目标差距驱动多轮深化交付物，写评分离、决策三级拍板、循环内零人工打断
5. **收敛**：目标覆盖门、独立评审门、开工就绪门全过
6. **终局批与交付**：一次性提交决策终批、豁免确认、交付物批准，登记后交付

## 三条核心机制

1. **唯一账本**：总控文档是全过程唯一记录——目标、事实、决策、差距、轮次日志、签批记录都在里面。换会话不丢，恢复以总控文档为唯一锚点。
2. **批准凭证唯一**：签批、豁免、批准、思路共识的凭证＝**你本人在文档上的评论链接**。会话里口头同意、让 AI 代发评论一律不作数。
3. **写评分离**：写交付物的不许自评，关闭差距的裁定归评估角色；记账角色只写总控文档。这是防 AI 自说自话的主要机制。

## 安装

本 Skill 是标准目录结构（`SKILL.md` + `references/`），任何支持 Skill 的 AI 助手都可以加载。

```bash
git clone https://github.com/tonywoo001/long-task-loop.git
```

- **豆包**：把 `long-task-loop` 文件夹放入豆包的 skill 根目录（如 `workspace/.user_skills/`），新会话生效。
- **WorkBuddy 等其他助手**：放入该助手的 skills 配置目录，按平台规则加载。
- 也可以直接下载仓库里的 `long-task-loop` 文件夹，复制到目标助手的 skill 目录。

## 用法

**触发方式：显式指令。** 本工作流不会自动抢任务，只有你明确说出以下意图时才启动：

| 阶段 | 触发语 |
|-|-|
| 开始 | 「梳理目标」「开始长任务」「跑奠基」 |
| 循环 | 「开始循环」「继续循环」 |
| 恢复 | 「恢复奠基」「恢复循环」＋总控文档链接 |

**你需要出场的时点：**

| 时点 | 要你做什么 |
|-|-|
| 奠基访谈全程 | 答问：目标、度量、范围、事实确认、选思路、交付物选型、缺口豁免 |
| 奠基出口 | 在总控文档上对三锁分别发批准评论（每锁一条） |
| 循环启动 | 明确说「开始循环」并附总控文档链接 |
| 终局一次批 | 一次处理：决策终批、豁免确认、交付物批准（以文档评论为准） |

**一条最要紧的规矩**：正式批准的唯一凭证是你本人在文档上的**评论链接**。会话里说「就这个吧」「同意」都不作数，只能当附注。

## 目录结构

```
long-task-loop/
├── SKILL.md                       # 六段工作流总纲 + 三角色纪律 + 15 条红线
└── references/
    ├── control-doc-template.md    # 总控文档十三章模板与关键行格式
    ├── readiness-gate.md          # 就绪门逐条判据、凭证标准、抽查规则
    ├── deliverable-contract.md    # 交付物契约：八设计面、可实施深度、互检与裁决链
    ├── report-spec.md             # 三份结构化汇报模板
    └── operation-discipline.md    # 关键检查报错处置、单点不作全局、证据留痕
```

## 来源

本 Skill 的能力提取自 [one-loopfordesign](https://github.com/Juuuulianxxx/one-loopfordesign)（v5.4.0）插件的核心工作流，做了平台无关化适配：去掉 Claude Code 专属机制（hooks、插件子代理、脚本门禁），把飞书通道抽象为「语义操作」，使同一套打法可复用于豆包、WorkBuddy 等任意 AI 助手。
