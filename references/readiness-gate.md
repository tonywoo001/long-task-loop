# 语义就绪门判据与通用评估规则（references/readiness-gate.md）

本文件定义就绪门逐条判据与输出格式、入场复验规则、启动指令凭证判据、抽查最小规则、高影响判定、放行凭证标准、开工就绪门输出规则、目标效力拷问清单。SKILL.md 一律引用本文件，不各自定义。

结构校验（章节齐全、格式正确）只作为附属检查，不是就绪的主判据。

## 一、就绪门逐条判据

评估角色逐子判据给出通过或不通过并引用证据；**全部子判据通过才放行，任一不过即整体不过**。结论落总控文档「就绪门与签批记录」章。

### 问一：目标指向根本问题且可判定达成

| 子判据 | 判定内容 |
|-|-|
| 一之一 | G0 终极目标以业务结果表述，不是以机制手段表述（写「用户提单一次通过率提到九成」而不是「加一个校验模块」） |
| 一之二 | 目标体系三层齐备：G0 终极目标、G1 评估对象的使命、G2 本循环的任务 |
| 一之三 | 每条 G0-N 细分目标都写明了判据——谁看什么数据、跑什么命令、比对什么结果即可判定达成；每条都能回链 G0 |
| 一之四 | 访谈记录中含至少一次对「为什么要做这件事」的下钻，并写下了下钻结论；结论指向根本问题而不是表面症状 |

探索性任务例外：确实无法确认唯一根因时，允许把「根因待探索」显式登记为已知未知并经用户确认，视同一之四通过；评估者不得凭直觉在同一条上反复退回。

### 问二：事实基线足以支撑方案推理

| 子判据 | 判定内容 |
|-|-|
| 二之一 | 每条事实都有内容、来源、核实方式、核实时间四项，缺任一项即该条不通过；核实方式写的是具体动作 |
| 二之二 | 高影响假设（判定见第五节）全部已核实，或已逐条进缺口清单 |
| 二之三 | 方案推理所需的现状（代码库、外部系统契约、线上数据）已用工具核实，不是仅凭用户口述记录 |
| 二之四 | 评估对象三层齐备且均为表格（层 A 主评、层 B 联动待解锁、层 C 只读参考）；各层只列文件与权限，运行环境类信息落运行上下文行 |

### 问三：方案框架与目标匹配

| 子判据 | 判定内容 |
|-|-|
| 三之一 | 交付物清单（层 A 表全量）与各自的完成定义齐备，都不为空、不含「待定」类字样 |
| 三之二 | 完成定义能回链业务目标——按完成定义做完即可判定目标达成 |
| 三之三 | 项目约束逐条具体可判定、从约 1 起连续编号，且无一条与铁律章的通用条文重复 |
| 三之四 | 最大轮次与 Token 预算两个字段都已填写（预算未设时写「未设」，不留空） |
| 三之五 | 交付物选型已经用户拍板：层 A 表与交付形态行逐项一致；产研工具类未另行选型时按默认两份登记，也算已拍板 |
| 三之六 | 存放位置已确认并写进运行上下文行 |

### 问四：思路基线已与用户对齐

| 子判据 | 判定内容 |
|-|-|
| 四之一 | 思路基线三表齐备：调研对标结论表（带来源）、候选思路对比表、选定与凭证表，无单行堆积 |
| 四之二 | 候选思路至少三个且实质不同——同一方向的参数微调不算不同候选 |
| 四之三 | 选定思路与理由引用具体的已核实事实或调研来源，不写「更简洁」「更合理」这类无来源判断 |
| 四之四 | 用户共识凭证在位：用户本人的文档评论链接（凭证标准见第六节） |
| 四之五 | 时序约束成立：思路调研在目标方向与用户对清之后才启动。判定证据＝业务目标章的目标体系与范围先落盘、思路基线段的调研结论晚于其落盘。目标未清就先调研的，本条不通过 |

### 输出格式

评估结论按下列格式逐条输出，主流程原样誊写进总控文档「就绪门与签批记录」章：

```text
就绪门评估 · 【YYYY-MM-DD】
- 一之一：【通过｜不通过】 · 证据：【总控文档章节位置或文件路径与行号】
- 一之二：【通过｜不通过】 · 证据：【…】
（按本文件第一节的全部子判据逐条列出，一条不落）
整体结论：【放行｜不放行】
不通过项的补齐要求：【逐条写清补什么才算通过｜无】
本次实际读取清单：【读过的全部文档与文件】
```

快速档不豁免就绪门：档位只影响访谈中事实核实的密度，不降低本节任何一条子判据。

## 二、入场复验规则

循环入场只做三查，**不重跑就绪门判据评估**：

1. **签批三行核验**：三锁签批行齐全（目标锁、事实基线锁、方案框架锁各有当前有效的一行），每行含锁名、用户评论链接与日期；抽读评论本体，确认发起者是用户本人且内容为批准语义。缺行、评论对不上、评论不是用户本人发出或内容不构成批准，即签批不实。
2. **摘录逐字比对**：把三锁要点摘录（目标一句话、G0-N 细分目标清单、完成定义、事实基线要点）与对应章节的当前内容比对。**一致的判定＝摘录各要素在对应章节内逐字可寻**，不做语义等价的自由裁量。
3. **循环前置待办清零核对**：逐项核对待办登记章「循环前置待办」组，全部已完成才算清零。

三查全过即放行入场；签批不实退回奠基补签；摘录不一致视为基线变更，走重签流程后再入场；前置待办未清零先清后入场。

**不采用文档版本号作复验基线**：签批与登记的写入动作本身就会推进版本号，用版本号判据会把每次入场都误判为「已变更」，复验永远无法稳定放行。

## 三、启动指令凭证判据

入场复验之外另有一项由**主流程**核对的硬条件：循环启动指令凭证。

- **凭证内容**：用户明确的「开始循环」启动语，形态可以是总控文档评论，也可以是会话指令；两者都登记链接或日期到「就绪门与签批记录」章的循环启动指令凭证行。
- **不算启动指令的三类**：提问、复核请求、条件确认。用户问「可以开始了吗」、要求「先复核一遍」、说「等某件事完成再说」，都不构成启动授权。
- **校验通过不等于授权**：就绪门全部子判据通过、入场复验三查全过，都只说明具备资格；**缺启动指令凭证一律不得开轮**，也不得以「条件已具备」自行推定授权。

## 四、抽查最小规则

各处「抽查」统一采用同一口径：**抽查条数不少于待查总数的三分之一且不少于三条**（总数不足三条时全查），**优先抽高影响项**。

适用场合：快速档访谈的事实抽核、签批与豁免评论本体的抽读、收敛评审对决策记录与轮次日志一致性的抽查、差距序号连续性与同义重开的抽查、事项登记行与决策行一一对账的抽查。

## 五、高影响判定

**影响交付物形态、外部接口、数据结构或安全边界的事项即为高影响。**

同一判据在三处复用，口径不得分化：就绪门问二的高影响假设、快速档抽核的优先项、二级影子拍板中重大取舍的判定（重大取舍至少三个从真实约束推导的备选）。

## 六、放行凭证标准

五类放行凭证：**三锁签批、缺口与差距的豁免、层 A 交付物的最终批准、思路基线共识**四类，以及停滞与达最大轮次的解除之**转收敛评审／终止任务／加预算**三处置，维持同一收紧标准；**停滞解除之扩轮至新最大轮次**走轻量档例外。

- 凭证形态：前述维持收紧标准的类别，凭证唯一为**用户本人在文档上的评论链接**（交付物批准为交付物文档或总控文档，以登记行记载的链接为准；其余为总控文档）；**停滞解除之扩轮**例外——接受用户会话指令直接生效、无需评论链接，AI 在总控停滞解除行补一条简洁扩轮记录（格式：扩轮记录 · 原上限【N】→ 新上限【M】 · 用户会话指令原文：「【原话】」 · 指令时间：【YYYY-MM-DD HH:MM】）即可续开。
- **会话授权、口头同意、AI 代发评论一律无效（停滞解除之扩轮除外）**：凭证字段填这三类内容的，视同未签批、未豁免、未批准、未解除、未达共识，机制上必须拒收。
- 口头同意的唯一去处（扩轮除外）：写进登记行的附注字段，并**同时在待办登记章「循环前置待办」组新增一条补评论待办**；补齐前该项不得当作已获凭证使用。
- 核验方式：评论链接类按第四节抽查最小规则抽读评论本体，确认发起者是用户本人且内容为批准语义；扩轮的简洁扩轮记录核对原上限、新上限、指令原文、指令时间四要素齐全即可。
- 与启动指令凭证的区别：启动指令凭证接受会话指令（见第三节），不在本节五类之内；两者不得互相援引放宽。

## 七、开工就绪门输出规则

开工就绪门单独评估，注入材料＝交付物文档链接（按层 A 表逐项）＋三个标量参数（逐份交付物的档位登记值、交付形态行的分型声明、项目仓路径）——**不含总控文档、轮次日志与其他过程材料**。本门「只看交付物、不看过程材料」防的是评估者拿过程材料反推结论，标量参数不构成过程材料。

输出三个清单，**三者皆空才通过，任一非空即不过门**：

| 清单 | 装什么 |
|-|-|
| 阻断性缺口清单 | 照方案做不下去的缺口：落点缺失、接口或数据结构未定、异常路径无交代、验证方式无法执行等，凡下游必须回头追问才能动工的即入本清单 |
| 无归属发现清单 | 方案里提到却没有归属的事项：写了风险没写谁处置、写了待确认没写找谁确认、写了依赖没写依赖方，凡「有发现无落点」的即入本清单 |
| 凭证缺口清单 | 方案中声明已获批准或已获豁免、却查不到对应凭证的条目；**已登记「待终局批」的影子决策与「待终局确认」的豁免项不算凭证缺口**——它们的凭证在终局介入时才产生 |

- 评审者须在结论末尾**自报本次实际读取过的全部文档与文件**，供抽查核对。
- 显式例外：实现方案「风险与未知项清单」中已获用户豁免的条目不算阻断性缺口；未获豁免的待定表述按其性质入阻断性缺口清单或无归属发现清单。

输出格式：

```text
开工就绪门 · 【YYYY-MM-DD】
- 阻断性缺口清单：【逐条列出｜无】
- 无归属发现清单：【逐条列出｜无】
- 凭证缺口清单：【逐条列出｜无】
结论：【通过｜不通过】
本次实际读取清单：【读过的全部文档与文件】
```

## 八、目标效力拷问清单

评估角色在开轮差距评估与收敛合并门两处按本清单四问逐问给「效力拷问结论」；评估回报缺该结论即报停立差距。

| 拷问 | 追问内容 | 合格判据 |
|-|-|-|
| 拷问一 · 承载层归属 | 方案每条关键约束由哪一层强制——机械、结构还是条文？ | 关键约束逐条可指认承载层，无「未标注」项 |
| 拷问二 · 失效路径 | 纯条文约束的失效路径是什么、失效时谁兜底？ | 每条条文级约束写明失效路径与兜底者 |
| 拷问三 · 环境强制机制盘点 | 环境里有什么可用的强制机制没被用上？ | 有逐项核查记录；「没用上」的写明理由 |
| 拷问四 · 落空推演 | 该目标落空的前三种最可能方式是什么？方案挡住了几种、靠哪层挡住？ | 三种方式逐一写明「已挡（哪层）／未挡（立差距）」 |
