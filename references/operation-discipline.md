# 操作核实纪律契约（references/operation-discipline.md）

本文件定义关键检查报错的处置阶梯、单点结果不作全局结论的规则、关键检查清单、检查结论的证据留痕要求。SKILL.md 一律引用本文件，不各自定义。

本契约管的是**怎么核实**，不是**核实什么算过**——判据类定义归 `readiness-gate.md`，产物形态定义归 `deliverable-contract.md`，本文件只约束执行核实动作时的行为。总控文档实例内的对应条文是铁 14（关键检查报错即停），条文与本契约同源。

## 一、报错即停

关键检查命令**非零退出**、**输出不可解析**、或**返回内容与请求对象对不上**时，一律不得取默认值继续。

- **禁止的默认值替代**：把报错当成「0 条」「无」「空」「通过」「不存在」中的任何一个。报错的含义是「这次没查到结果」，不是「查到的结果是零」——两者在账目上是完全不同的事实，混同一次就会让后续全部结论建立在假事实上。
- **处置阶梯（固定两级，不增不减）**：
  1. **重试一次**。文档通道调用存在瞬时错误，一次重试能消解绝大多数误报。
  2. **仍失败即报停上报用户**：说明哪条检查、什么错、已重试一次、当前卡在哪一步、需要用户做什么。
- **禁止的三种绕行**：重试超过一次后自行判定「大概是没有」；换一条不等价的命令拿到能跑通的输出后当作原检查的结果；把失败的检查从流程里悄悄跳过。
- 报停不是失败，是把不确定性交还给能解决它的人；带着假事实继续跑才是失败。

## 二、单点不作全局

抽样结果或单条查询结果**不得写成全称结论**。

- 「某文档无未解决评论」不等于「全部文档无未解决评论」；「抽查的三条差距序号连续」不等于「差距序号全程连续」。
- 全称结论必须有两类支撑之一：**全量清点**，或**符合抽查最小规则的抽查**（不少于待查总数的三分之一且不少于三条，总数不足三条时全查，优先抽高影响项——口径见 `readiness-gate.md` 第四节）。
- 无论哪一类，结论都必须**写明清点范围**：查了哪些对象、查了几条、总数是多少。范围写不出来的结论，按未核实处理。
- 单点结果本身可以写，但要写成单点的样子：写「文档 X 未解决评论 0 条（仅查 X）」，不写「评论已清零」。

## 三、关键检查清单

本清单枚举受本契约约束的检查动作，随契约版本增补；清单内的每一项，执行时都必须走第一节的报错即停阶梯，结论都必须满足第二节的要求。

| 检查动作 | 出现在哪 |
|-|-|
| 未解决评论清点 | 奠基出口、每轮第一步、收敛触发前置硬条件 |
| 签批、豁免、启动凭证的评论本体核验 | 入场复验、放行凭证核验 |
| 三锁要点摘录与对应章节的逐字比对 | 入场复验、每轮第二步 |
| 交付物版本号（revision）读取 | 终局介入登记、交付前复核 |
| 文档链路探测 | 段一启动、循环入场 |
| 存放位置可达校验 | 奠基开场存放位置探测 |

清单外的检查不因未列入而豁免本契约——列举是为了把最容易被吞掉的几处点名，不是为了划出免责区。

## 四、证据留痕

关键检查的结论必须附**所执行的检查动作**与**输出要点**，供对账抽查。

- 证据形态：动作描述（或等价的具体操作）＋ 关键输出（计数、条目、结论之一），不要求贴全文。
- 落点：结论写进哪份文档，证据就跟到哪一行；就绪门评估结论的证据落总控文档「就绪门与签批记录」章，每轮检查的证据落轮次日志与循环区对应块。
- **没有证据的结论按未核实处理**：评估侧抽查时对不上证据的条目，一律退回重核实，不接受「我查过了」这类无痕陈述。
- 报停时同样留痕：把报错原文要点与已重试一次的事实写进上报内容，用户才能判断是环境问题还是数据问题。
